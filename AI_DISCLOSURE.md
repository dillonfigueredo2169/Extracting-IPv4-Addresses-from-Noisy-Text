## What came back and what was wrong

The code from prompt 2 passed all 39 test cases. But testing it with Windows line endings (`\r\n`) found a bug. `std::getline` leaves the `\r` at the end of the line, so the line reads `END\r`, which does not match `END`, and the program never quits. It just prints "Invalid input" and keeps asking until the input runs out. The spec says the loop has to stop when the user enters END, so this would be a real problem on Windows.

The code from prompt 1 strips a trailing `\r` before comparing, so it handles this correctly. I tested both versions with the same `\r\n` input to confirm.

Because of this, I kept the prompt 1 code as my final submission. The prompt 2 output is included only so the comparison can be seen.

## How the final code works

`extractIPv4` goes through the line and cuts it into runs of digits, periods, and colons. Any other character ends a run. Each run is passed to `parseToken`, which checks for exactly four octets separated by periods, and an optional colon and port at the end. If anything is left over, or any number is wrong, the whole run is thrown out and scanning moves to the next run. It never looks for a smaller address inside a bad run. The first run that fully matches is returned.

`parseNumber` counts the digits before doing any math, so an octet longer than 3 digits or a port longer than 5 is rejected before it can overflow. It also rejects leading zeros like `01`, `00`, and `080`, but allows a plain `0`.

Decisions the spec left open:
- If a line has two valid addresses, the first one is returned, since only one address can be extracted per line.
- After an invalid run, scanning keeps going, so `1.2.3.4.5 10.0.0.1` gives `10.0.0.1`.
- `END` has to match exactly. `END ` with a trailing space is treated as normal input.

### My own test cases

I added these two tests myself (they're at the bottom of `tests.txt`).

`ip is 1.2.5.6.8000`

This checks what happens when someone writes a port with a period instead of a colon. It could look like address `1.2.5.6` with port `8000`, but the grammar only allows a colon before the port, and `1.2.5.6.8000` is one run with five parts. The whole run has to be rejected, not cut down to `1.2.5.6`. The program correctly printed `Invalid input: no valid IPv4 address found`.

`ip is 168.20.2900`

This checks an address that is broken in two ways at once. It only has three parts instead of four, and the last part, `2900`, has four digits and is over 255. The program correctly rejected it with `Invalid input: no valid IPv4 address found`.

With both of my tests added, all 41 tests pass.
